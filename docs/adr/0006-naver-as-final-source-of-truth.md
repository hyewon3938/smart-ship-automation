# ADR-0006: 네이버를 발송 상태의 최종 원천으로 삼는 3단 역동기화

- **Date**: 2026-08-10
- **Status**: Accepted
- **이슈**: —

## Context

ADR-0005에서 로컬이 서버에 그룹 상태를 물어 반영하는 pull 역동기화를 도입했다.
운영해 보니 두 가지 사각지대가 드러났다.

1. **트리거 공백** — 역동기화 호출 지점이 셋(동기화 버튼, 수동 발송, 예약 큐 소진)뿐이고
   모두 로컬 발 사용자 행동이다. 예약 큐가 비는 시점은 서버가 운송장을 잡기 몇 분 전이라
   항상 헛돌았고, 그 뒤로는 사용자가 동기화 버튼을 누를 때까지 아무 일도 일어나지 않았다.
   실제로 서버가 14:15에 발송처리한 그룹이 다음 날까지 로컬에서 "예약완료"로 남았다.

2. **원천 공백** — 대조 대상이 `createdAt` 2주 이내로 잘려 있어, 그 창을 벗어난 미완결
   그룹은 어떤 경로로도 정리되지 않았다. 창을 걷어내도 절반만 해결된다. 서버 도입 이전에
   예약된 그룹은 서버 DB에 기록 자체가 없어 `{states: []}`가 돌아오기 때문이다.
   실제로 10개 그룹이 이 상태였고, 네이버에는 전부 배송완료·구매확정으로 기록돼 있었다.

즉 "서버가 발송의 주체"라는 ADR-0005의 전제는 맞지만, **서버가 발송 기록의 유일한 보관처는
아니다.** 네이버가 발송처리의 최종 수신자이자 영구 기록처다.

## Decision

역동기화를 트리거·원천 두 축으로 나눠 3단으로 구성한다.

| 단계 | 원천 | 트리거 | 대상 |
|------|------|--------|------|
| 주기 대조 | 서버 | 대시보드 2분 주기 + 탭 복귀 | 로컬 미완결 그룹 전체 (기간 제한 없음) |
| 동기화 대조 | 서버 | 동기화 버튼·수동 발송·예약 큐 소진 | 동일 |
| 원천 대조 | **네이버** | 동기화 버튼만 | 24시간 이상 묵고 운송장도 없는 예약완료 그룹 |

- 주기 대조는 `POST /api/orders/reconcile` (로컬 전용, 네이버 호출 없음)로 분리해
  2분마다 돌아도 외부 API를 건드리지 않게 한다.
- 네이버 대조는 판정을 보수적으로 한다. 발송 이후 상태(`DELIVERING`/`DELIVERED`/
  `PURCHASE_DECIDED`/`EXCHANGED`)가 하나라도 있고 **발송 전 상태(`PAYED`/`PAYMENT_WAITING`)가
  전혀 없을 때만** 발송완료로 확정한다. 취소·반품만 남은 그룹은 확정하지 않는다.
- 상태를 바꾼 주체를 예약 로그에 남긴다("서버 발송처리 확인" / "네이버 발송처리 확인").

## Alternatives

- **네이버 대조도 2분 주기에 포함** — 가장 단순하지만, 확정되지 않는 그룹(예: 예약만 되고
  실제로는 발송되지 않은 건)에 대해 하루 720회의 무의미한 외부 API 호출이 발생한다.
  Rate limit을 잠식하는 대가로 얻는 게 없다. 사용자가 동기화를 누르는 시점이면 충분하다.
- **서버 DB를 로컬 기록으로 백필** — 사각지대의 근본 원인(서버가 모르는 그룹)을 없애지만,
  로컬이 "발송됐다"고 주장하는 데이터를 발송 주체인 서버에 밀어 넣는 역방향 신뢰가 된다.
  ADR-0005의 단방향 신뢰(발송 필드는 항상 서버가 진실)를 깬다.
- **묵은 그룹은 수동 삭제** — 지금까지의 사실상 정책. 삭제하면 기록이 사라져 "발송했는지"
  자체를 잃는다. 실제로 배송까지 끝난 주문을 없던 일로 만드는 셈이라 매출 대조가 불가능해진다.
- **`booked` 상태에 만료 시각을 두고 자동 폐기** — 정리는 되지만 근거 없이 상태를 바꾼다.
  잘못 폐기하면 실제 미발송 주문을 놓친다.

## Consequences

- (긍정) 서버 기록이 없는 그룹도 정리된다. 도입 시점에 남아 있던 10개 그룹이 네이버 기준
  운송장·발송일과 함께 발송완료로 확정됐다.
- (긍정) 서버 DB가 초기화되거나 교체돼도 로컬이 네이버로부터 스스로 복구할 수 있다.
  서버 DB를 백업 대상으로 승격시키지 않아도 된다.
- (긍정) 대시보드를 열어두면 사용자가 아무것도 누르지 않아도 발송 결과가 반영된다.
- (부정) 동기화 버튼의 응답 시간이 네이버 조회 1회만큼 늘어난다. 대상이 없으면 API를
  호출하지 않으므로 평상시에는 비용이 없다.
- (부정) 판정을 보수적으로 한 대가로, 부분 취소가 섞인 그룹은 자동 정리되지 않고 남는다.
  의도된 트레이드오프 — 잘못 확정하는 쪽이 더 비싸다.
- (모니터링) 24시간 기준은 임의값이다. 예약이 밤늦게 몰리는 날 정상 그룹이 대조 대상에
  들어올 수 있다. 그 경우에도 네이버가 `PAYED`로 답하므로 상태는 바뀌지 않지만,
  불필요한 조회가 반복되면 기준 시간을 늘린다.
