# ADR-0004: 예약 후 1시간 하이브리드 스크래핑 — 절대 시각 윈도우 + 예약 상대 창

- **Date**: 2026-07-19
- **Status**: Accepted
- **이슈**: (본 변경 PR에서 연결)

## Context

운송장 자동 스크래핑은 8~18시 KST의 **절대 시각 윈도우**(`isWithinScrapeWindow()`,
`dispatch-worker.ts`)에서만 돈다. 이 방식은 윈도우 밖 예약을 커버하지 못한다:

1. **밤/이른 아침 예약 방치**: 18시 이후·8시 이전에 예약을 마치면 자동 폴링이 운송장을
   잡지 않아, 다음 윈도우(다음날 8시)까지 발송이 밀린다.
2. **가장 좋은 스크래핑 창을 놓침**: 예약 직후는 GS 세션이 방금 로그인/예약으로 살아있어
   스크래핑 성공률이 가장 높다. 그런데 그 창이 윈도우 밖이면 활용하지 못한다.
3. **절대 시각 확대의 한계**: `#63`(c716d5e)에서 하한을 11→8시로 낮췄지만, 여전히 절대
   시각이라 밤 예약은 못 잡고, 넓힐수록 처리할 예약이 없는 유휴 폴링만 늘어난다.

ADR-0003은 이 상황을 **수동 "지금 발송처리" 버튼**으로 해결했으나 매번 사람이 눌러야 하고,
그 버튼(`DispatchPanel`)은 2026-04-13(#28) 서버 대시보드 개편 때 대시보드에서 빠진 뒤
줄곧 어디에도 마운트되지 않아 실제로는 화면에서 쓸 수 없는 상태였다.

## Decision

스크래핑 허용 조건을 **하이브리드**로 바꾼다:

```
scrapeAllowed = isWithinScrapeWindow() || hasRecentlyBookedGroup(bookedGroups)
```

- 기존 절대 시각 윈도우(8~18 KST)를 **안전망으로 유지**한다.
- 여기에 더해, **예약 완료 후 1시간 이내** booked 그룹이 하나라도 있으면 시간과 무관하게
  스크래핑한다(`RECENT_BOOKING_WINDOW_MS = 60분`).

이를 위해 `orders` 테이블에 **`bookedAt` 컬럼을 신설**한다. booked 전환 시점(로컬 예약 완료,
서버 upsert, 방문택배 매칭, 수동 상태변경)에 `COALESCE(booked_at, now)`로 **최초 1회만** 기록해,
재동기화가 반복돼도 1시간 창이 밀리지 않게 한다. 컬럼은 `db/index.ts`의 런타임
`addColumnIfNotExists`로 로컬·서버 DB에 자동 반영한다.

아울러 ADR-0003의 `DispatchPanel`을 **로컬 대시보드에 재연결**한다(`!isServerMode`일 때
마운트). 자동화가 못 잡는 예외(세션 만료 등)용 수동 백업으로 살려둔다.

## Alternatives

- **(A) 시간 윈도우 완전 제거(24시간 상시)**: 가장 단순하지만, 운송장이 영영 안 뜨는
  booked 잔재(예약 실패·취소 등)에 매 폴링 스크래핑 요청이 나가 GS 봇 감지·세션 소모를
  키운다. 상대 창(1시간)이 이 무한 요청을 자연히 닫아준다. 기각.
- **(B) 예약 후 1시간만(기존 윈도우 폐지)**: 1시간 내 운송장을 못 잡은 건이 자동 재확인
  경로를 잃어 방치·수동 처리로 떨어진다. 낮 시간대 안전망 상실. 기각.
- **(C) `bookedAt` 없이 `updatedAt` 재활용**: `updatedAt`은 운송장 감지·발송 등 후속 write마다
  덮어써져 "예약 시각"이 아니다. 이를 기준점 삼으면 1시간 창이 계속 밀려 무한 스크래핑이
  된다. 전용 컬럼 신설로 대체. 기각.
- **(D) 절대 윈도우만 더 넓히기(예: 6~22시)**: 밤 예약을 여전히 못 잡고, 예약 유무와 무관한
  시각 기반이라 유휴 폴링만 늘어난다. "예약이 있을 때 그 직후 확인"이라는 목표에 미달. 기각.

## Consequences

### 긍정
- 아침·밤 예약도 **예약 직후(세션 live)** 자동으로 운송장을 확보 → ADR-0003 수동 버튼의
  주 사용처를 자동화, 수동 개입 빈도를 낮춘다.
- 상대 창(1시간) + 절대 윈도우(8~18시) 병행 → 1시간 내 미배정 건은 낮 윈도우가 이어받아
  **방치가 없다**.
- 1시간이 지나면 상대 창이 닫혀 **무한 스크래핑 방지**(booked 잔재 보호).
- `COALESCE` 기록으로 재동기화 시 창이 밀리지 않는다.

### 부정 / 모니터링 포인트
- **심야 발송**: 밤/새벽에 운송장을 잡으면 자동모드에서 그 시각에 네이버 발송처리도 나간다.
  "시간 무관" 요구의 의도된 결과지만, 심야 발송 알림이 CS상 문제가 되면 스크래핑과 발송의
  시간대를 분리하는 후속 설계가 필요하다.
- **방문택배는 범위 밖**: 방문택배 매칭 게이트(`dispatch-worker.ts` step 0)는 여전히 절대
  윈도우만 쓴다. 방문택배는 `booking` 상태(사용자 결제 대기)라 `bookedAt`이 없어 상대 창을
  적용할 수 없다. 심야 방문택배 매칭이 필요해지면 booking 시작 시각 기반 별도 설계 필요.
- **DispatchPanel 재연결의 이중 갭 해소**: 과거 마운트는 서버 전용(`{isServerMode && ...}`)
  이었는데 버튼은 로컬 전용 가드(`!isServerMode`)라, 옛 코드를 되살려도 노출되지 않았다.
  로컬 대시보드에 마운트해야 실제로 보인다는 점을 반영해 연결했다.

### ADR-0003과의 관계
Supersede 아님(**보완**). ADR-0003의 수동 즉시 발송은 세션 만료·자동화 실패 시 백업으로
여전히 유효하다. ADR-0004는 그 주 케이스(윈도우 밖 예약)를 자동화한다.
