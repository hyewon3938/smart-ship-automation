# ADR-0002: 발송인은 GS 주소록 이름 매칭으로 설정

- **Date**: 2026-06-07
- **Status**: Accepted
- **이슈**: #64

## Context

GS택배(cvsnet.co.kr)는 예약 폼에서 발송인을 직접 입력하는 방식이 아니라 "나의 주소록"에
미리 등록된 항목을 선택하는 구조다. Playwright 자동화는 주소록 레이어에서 발송인 이름
텍스트를 매칭해 해당 항목을 클릭한다. 발송인의 전화·주소·우편번호는 주소록 항목에 이미
저장돼 있어 예약 폼에 따로 입력할 필요가 없다.

기존 코드는 발송인 이름을 `"리커밋"`으로 하드코딩했고, 설정(`SenderSettings`)에는
전화·주소·우편번호 입력 필드가 있었으나 **자동화가 전혀 읽지 않는 고아 상태**였다
(게다가 설정 페이지에 탭조차 렌더링되지 않아 UI에서 접근조차 불가능했다). 제3자가 fork해
자기 발송인으로 쓰려면 이 하드코딩을 설정값으로 일반화해야 했다.

## Decision

발송인 설정을 **"주소록 발송인 이름" 단일 값**으로 통일한다.

- `GsSettings`에 `senderName` 통합 (DB 키 `gs.senderName`, env 폴백 `SENDER_NAME`)
- 자동화는 이 값으로 주소록 항목을 매칭/검증
- 미설정 시 명확한 안내 후 중단 (엉뚱한 발송인 자동 선택 방지)
- 미사용 `SenderSettings`(전화·주소·우편번호)와 렌더링되지 않던 `SenderSettingsTab` 제거

## Alternatives

- **폼 직접입력 자동화**: 발송인 정보를 예약 폼에 직접 타이핑. 주소록 미등록으로도 동작하나
  GS 폼 구조 재분석이 필요하고, 주소록 선택이 GS가 의도한 UX. ROI 낮음.
- **전체 `SenderSettings`(전화·주소·우편번호) 유지**: 자동화가 안 쓰는 필드를 남기면
  "입력하면 반영될 것 같은" 오해를 유발(고아 설정). UI와 실제 동작이 불일치한다.

## Consequences

- (긍정) 설정 단순화, UI = 실제 동작 일치. fork 사용자는 GS 주소록에 발송인 1회 등록 +
  이름 입력만 하면 된다.
- (긍정) 기본값을 env 폴백(`SENDER_NAME`)으로 두어 기존 운영 환경은 무변화.
- (부정) 발송인 변경 시 GS 주소록과 설정 양쪽을 수정해야 한다.
- (부정) 주소록에 동명이인이 있으면 첫 매칭 항목을 선택한다 (기존 로직과 동일, 실사용 문제 없음).
- (모니터링) 설정한 이름이 주소록에 없으면 예약이 명확한 에러로 중단된다 — 사용자가
  설정/주소록 불일치를 즉시 인지할 수 있다.
