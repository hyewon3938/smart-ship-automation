# ADR-0003: 윈도우 밖 수동 즉시 발송 — 로컬 트리거 + 서버 단독 발송 + 세션 live 프로브

- **Date**: 2026-07-04
- **Status**: Accepted
- **이슈**: #66

## Context

운송장 스크래핑은 8~18시 KST 윈도우에서만 자동으로 돈다(ADR-0001, `dispatch-window.ts`).
이 시간대 밖에 예약을 마치면 다음이 겹쳐 발송처리가 막힌다:

1. **윈도우 게이트**: `checkAndDispatch`의 스크래핑 단계가 `isWithinScrapeWindow()`에 막혀
   운송장을 잡지 않는다 → 발송처리로 이어지지 않음. 기존 "운송장 동기화" 버튼도 같은
   `checkAndDispatch`를 호출하므로 저녁엔 무력하다.
2. **세션 idle 만료**: 윈도우 밖엔 2분 폴링이 없어 GS 세션을 keep-alive 못 한다. GS 세션은
   몇 시간 만에 idle로 죽는다.
3. **유효성 오판**: `checkCookieValidity()`가 쿠키 **파일 나이(24h)**만 검사 → 파일은
   신선한데 세션이 죽은 상태를 "유효"로 보고한다. 2026-07-04 실제 발생: 20:09 로그인 →
   22:10 예약조회가 302(로그인 리다이렉트)인데도 파일 기준으론 "유효".

이 상황에서 발송하려면 재로그인 → 운송장 스크래핑 → 서버 반영 → 발송처리를 수동으로
일일이 밟아야 했다(2026-07-04 저녁 7건을 그렇게 처리). 이를 버튼 하나로 재사용 가능하게
만들되, 로컬↔서버 역할 분리(로컬=예약/로그인, 서버=스크래핑/발송)를 깨지 않아야 한다.

## Decision

**로컬(Mac) 대시보드 전용 "지금 발송처리" 버튼**이 아래를 오케스트레이션하고, 실제 네이버
발송처리는 **서버가 단독으로 즉시 수행**한다:

1. `probeGsSession()` — 예약조회 페이지를 실제 fetch하여 200(live)/302(만료)로 세션 확인
2. 만료면 기존 headed 로그인 흐름을 트리거(캡챠는 사용자) 후 재시도
3. booked 주문의 예약번호로 `scrapeTrackingNumbers()`를 **직접 호출**(윈도우 게이트 우회)
4. 스크래핑한 운송장을 `/api/internal/dispatch-now`로 서버에 넘기면, 서버가 자동모드와
   무관하게 즉시 `dispatchBookedGroups()`로 네이버 발송처리

발송 로직은 `checkAndDispatch`에서 `dispatchBookedGroups(orderIds?)`로 추출하여 워커(자동)와
새 엔드포인트(수동)가 공유한다. `getBookedOrderGroups()`가 `status='booked'`만 반환하므로
발송 완료된 건은 재조회에서 빠져 이중발송을 막는다.

## Alternatives

- **(A) 로컬이 네이버로 직접 발송**: 로컬 `checkAndDispatch`가 이미 발송 로직을 가지고 있어
  구현은 짧다. 그러나 서버 워커도 같은 주문을 발송하려 해 **이중발송 레이스**가 생기고,
  "발송은 서버" 역할 분리를 로컬로 옮기게 된다. 기각.

- **(B) 서버(폰) 대시보드 버튼**: 이동 중 폰에서 누르고 싶을 수 있으나, 서버는 캡챠 로그인을
  띄울 수 없다. 게다가 저녁엔 세션이 죽어있는 경우가 많아 "Mac에서 로그인 필요" 안내만
  반복하는 반쪽 기능이 된다. 로컬 우선, 서버는 향후 별도 검토. 기각.

- **(C) 서버 2분 자동폴링에 위임**: 운송장만 서버에 넣고 기존 워커가 발송하게 두면 새 코드가
  가장 적다. 그러나 최대 2분 지연 + 자동모드가 켜져 있어야 동작 + 버튼 직후 결과를 못 보여줌.
  "버튼 누르면 발송된다"는 목표에 미달. 기각.

- **(D) mtime 기반 세션 체크 유지**: 추가 요청이 없어 가볍지만, 파일 신선/세션 사망을
  구분 못 해 오판한다(위 Context 3). 버튼의 신뢰성을 해치므로 기각, live 프로브로 대체.

## Consequences

### 긍정
- 저녁·세션만료 케이스를 **원버튼**으로 복구. 2026-07-04 수동 7단계 → 클릭 1회.
- **서버가 유일한 발송 주체** 유지 → 이중발송 없음, 서버 대시보드가 자연히 최신.
- 자동모드 on/off와 **무관하게** 동작(수동 = 명시적 액션).
- **정확한 세션 확인** — 프로브가 배너/버튼 신뢰성을 올림.
- 발송 로직 추출로 워커·수동 경로가 한 코드를 공유(중복 제거).

### 부정 / 모니터링 포인트
- **로컬 전용** — 폰에선 못 누른다(캡챠·쿠키 제약상 불가피). 향후 서버 fast-path는 별도.
- **프로브 요청 1회 추가** — on-demand(버튼 클릭 시)만이라 봇 감지 영향 미미.
- **dispatch-now ↔ 워커 폴링 레이스** — 좁은 창이지만, 발송 직전 `pending_dispatch` 재확인 +
  네이버가 이미 발송된 주문을 거절하는 멱등성으로 완화. 실패 건은 로그로 추적.
- **운송장 미배정 케이스** — 저녁 발송이 GS/CJ에 아직 안 뜨면 스크래핑이 null → "미배정"
  안내. 이땐 재로그인으로 쿠키가 살아있으니 다음날 8시 자동 윈도우가 이어받는다.
